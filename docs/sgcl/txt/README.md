# sgcl::txt

What a human expects of text and a byte does not give: the properties of a code point, the boundaries between graphemes, words and lines, normalization, the full case mappings, the order of a language, and the encodings. `#include "sgcl/txt/txt.h"` brings the module in; it depends on [`core`](../core/README.md) and [`containers`](../containers/README.md) and on nothing else — never on `async` or [`io`](../io/README.md) — and `net` and the user interface are built on it. The index of the whole interface is [`docs/sgcl/`](../README.md).

## What is here and what is in core

[`core`](../core/utf8.md) has text at the level of bytes and code points: `utf8` (decoding, encoding, validation), `unicode` (the simple case mappings, one code point to one, and the White_Space property), `runes` (the code points of a text, decoded as they are walked) and the whole text interface of `string` and `slice`. That does not move, and this module does not repeat it: `txt` only adds what needs the larger tables and the algorithms of the annexes.

| | |
|---|---|
| [properties](properties.md) | the general category, `is_alpha`, `is_digit`, `is_punct`, `is_mark`, `is_printable`, `is_emoji`, the value of a digit, the script, and `columns`: the cells a code point and a text take on a terminal |
| [segment](segment.md) | the boundaries of UAX #29 and #14: `graphemes` (what a reader calls a character), `words`, `sentences`, `line_breaks`, the cursor moves over graphemes, and `wrap` and `truncate` over columns |
| [normalize](normalize.md) | the four forms of UAX #15 (`nfc`, `nfd`, `nfkc`, `nfkd`), `is_normalized` by the quick check properties, and `equal_normalized`, `compare_normalized`, `hash_normalized` for text that must compare the same however it was written |
| [case](case.md) | the full mappings, where a letter may become two ("straße" is "STRASSE") or depend on what stands around it or on the language: `to_lower_full`, `to_upper_full`, `to_title`, `fold_case`, `equal_fold_full`, and `locale` |
| [search](search.md) | `searcher` (a pattern prepared once, Boyer–Moore–Horspool), `find_fold` blind to case and `find_normalized` blind to the way a text was written, both reporting the position in the original |
| [encoding](encoding.md) | UTF-16 and UTF-32 in both directions, the 27 single byte encodings of the WHATWG's list (ISO-8859-2 to -16, KOI8-R and -U, windows-874 and -1250 to -1258, IBM866, the two Mac ones), `detect_bom` and `encoding_from_name` for what a header says |
| [format](format.md) | `format` and `format_to`: the pattern of `std::format`, read where the program is compiled, with the field of a text measured in the columns it takes and a precision that stops on a code point |
| [bidi](bidi.md) | text that runs both ways at once (UAX #9): `direction_of`, `paragraph_direction`, `levels`, `visual_order` and `bidi_runs` — the pieces in the order they are drawn, for whoever draws them |
| [collate](collate.md) | the order a reader expects (UTS #10): `collator`, a comparator and a sort key, three strengths; the root order of the DUCET and what 88 languages do differently, from CLDR |

## The rules of the module

**A code point and nothing else.** Every name that asks about a character takes a `char32_t` and refuses everything else: a `char` is a byte of UTF-8, not a character (`is_space(s[0])` on a no-break space asked about `0xC2`), and `'ż'` in a UTF-8 source is a multi-character literal of type `int`. The refusal is a deleted overload, and the names are objects rather than functions so that each is still passable where a predicate is asked for: `s.runes().count_of(txt::is_alpha)`.

**The library's types in the interface.** Text comes in as a [`string`](../core/string.md) or a [`slice<const char>`](../core/slice.md) and goes out as one: both hold the object the characters live in, which a `std::string_view` does not. A range this module hands back — the graphemes of a text, its words — is a range of the library ([`mixin::enumerable`](../core/mixin/enumerable.md)) over a slice that holds the text, decoded as it is walked and allocating nothing per element, as [`runes`](../core/utf8.md) is: a loop over a temporary is safe.

**Nothing throws and nothing is refused.** An invalid byte is `U+FFFD`, as it is in core; a code point no encoding can carry is `'?'`. An `optional` or a `result` appears only where an operation can really fail, such as a name of an encoding nobody knows.

**Its own implementation, from the specification.** Every algorithm here is written from UAX #9, #11, #14, #15, #29 and UTS #10; other implementations are used in the tests as an oracle and nowhere else, which is what ICU is to the collation tailorings. The test files of the UCD (`GraphemeBreakTest.txt`, `WordBreakTest.txt`, `LineBreakTest.txt`, `NormalizationTest.txt`) are the oracle the segmentation and the normalization are held to.

## The tables

`tools/unicode_tables.py` generates them all, into `sgcl/core/detail/` for core and `sgcl/txt/detail/` for this module: sorted ranges of code points, a binary search per question, ASCII answered without a table. What Python's `unicodedata` knows (the general category, the case mappings, East_Asian_Width) is taken from it; what it does not (the scripts, the emoji properties, the break properties) is read from the UCD files, which the script downloads once into `.ucd/<version>/` and asserts to declare the same Unicode version as the Python that runs it — otherwise "one source" would drift apart the day the Python changes. The generated headers are committed; the data is not.

Unicode 16.0.0 today, `txt::version` and [`unicode::version`](../core/utf8.md) the same string; the tailorings are CLDR 46. The eight headers above are 594 KB of tables: 42.6 KB for the properties, 63.1 KB for the boundaries, 78.2 KB for the normalization, 9.6 KB for the case mappings, 32.6 KB for the 27 single byte encodings, 11.2 KB for the bidirectional algorithm, and 356.8 KB for the collation — 255.5 for the root order and 101.3 for the 88 languages, which is the one table that is bigger than the rest put together. A program carries only the tables it asks about: one that only calls `is_alpha` links 16.7 KB and nothing else, and the linker drops the rest without a flag.

**How a table is shaped.** A question asked about one character in the middle of a loop is answered below U+10000 by a two-stage table — an index that says which block of values a code point falls in, the blocks themselves, and every block that is the same as another stored once — which is two reads and no branch. It replaced a binary search over sorted ranges that was a dozen steps no processor can predict: 21.8 ns against 0.54 measured over Latin text, and over the whole module `line_breaks` went from 82 ns a byte to 20, `words` from 26 to 8, a collation comparison from 443 ns to 51 — and the ASCII paths below took the first two further still. A set of code points is the same thing with a bit to the character. Above U+10000 the sorted ranges stay, since an index over a million code points would cost more than the search it saves and hardly any text goes there; the generator picks the block size and the width of the index per table, whichever comes out smallest, and three of the ten tables came out smaller than the ranges they replaced. The whole change cost 50.1 KB, a tenth of the module.

**And what Latin text does not have to be asked.** Most text is a run of ASCII letters, and for a run of them several of the rules have one answer: two ASCII characters are always separate graphemes unless they are a carriage return and a line feed (GB3), a run of letters is one word (WB5) and holds together on a line (LB28), and the case of a Latin letter is one bit with no mapping that changes a length, depends on its neighbours or spells an i the Turkish way. So the run is walked in one step rather than one step a character, found eight bytes at a time by a mask over a word — no instruction the compiler would not write by itself. `to_upper_full` over ASCII went from 11.1 ns a byte to 0.11 and `fold_case` from 9.7 to the same, the grapheme rule from 6.5 to 1.8, `line_breaks` from 22 to 12, `words` from 10.3 to 7.3. What is left in those three is not the rules but the piece of text each boundary hands back: a [`slice`](../core/slice.md) holds the object its characters live in, and making one costs about 3.9 ns. Every algorithm is held to the UCD's own test files, every case of each — 20103 break cases, 19965 lines of the normalization conformance file, the 2981 code points that have a case, 91707 bidirectional cases and 206286 lines of the collation conformance file — with no rule tailored and none skipped; the tailorings, which have no conformance file, are held to ICU.
