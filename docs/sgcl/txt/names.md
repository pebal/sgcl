# sgcl::txt display names

```cpp
#include "sgcl/txt/names/pl.h"      // the names in Polish
#include "sgcl/txt/names/de-CH.h"   // in Swiss German, which includes de.h
#include "sgcl/txt/names/all.h"     // every locale's
```

The names of languages, regions, scripts, currencies and time zones in a language are optional headers, one a
locale, for the 564 locales CLDR 46 rates modern or moderate and their variants (DESIGN 493, 494): a program
includes the languages it shows and pays for those alone. A header holds its locale's names as constant tables and
registers them when it is included — an inline variable whose initialization links the table into a lock-free list,
once a program however many translation units include it; nothing is called and nothing managed is made. A variant
(`de-CH.h`, `pt-PT.h`, `en-GB.h`) holds what differs from its CLDR parent and includes the parent's header, so
including it is enough. `all.h` includes them all, for a server answering any Accept-Language.

The names are asked of the values they name: [locale::display_name](locale/display_name.md),
[region::display_name](region/display_name.md), [script_code::display_name](script_code/display_name.md),
[currency::display_name](currency/display_name.md) (with its plural forms, which a
[number_format](number_format/README.md) writes with `currency_display::name`: "5,00 złotego polskiego"), and in
[time](../time/README.md) the zones of a date pattern (`z`, `zzzz`, `v`, `vvvv`, `VVV`, `VVVV`: "CEST", "czas
środkowoeuropejski letni", "czas: Polska"). A name is looked up in the locale's header, then in its parents'
(`de-AT` reads `de.h`); where none of them is included the codes come back (`DE`, `PLN`, the localized GMT format
for a zone), and a Debug build says once a locale which header would give the names. Each language's own name, its
autonym, is built in ([locale::autonym](locale/autonym.md)). A language's header is about 50 to 110 KB of source
(its names, most of it text), a variant's a few; all of them 9.4 MB.

## Rules

- Include a header in any translation unit: the names are then known to the whole program. A name asked
  before main by a global's initializer may come before a header's registration.
- The headers are generated by `tools/cldr_tables.py --names` from CLDR 46, like the rest of the locale data. The
  currencies are those a region uses today and the codes of `X`; the names of tags ("British English") are left out,
  a locale's name being composed of its parts as ICU's standard names are.

## Example

```cpp
#include "sgcl/io.h"
#include "sgcl/txt.h"
#include "sgcl/txt/names/de-CH.h"
#include "sgcl/txt/names/pl.h"

using namespace sgcl;

int main() {
    txt::locale supported[] = {txt::locale("pl"), txt::locale("de-CH")};
    for (auto l : supported) {
        println("{}: {} | {} | {}", l.autonym(), txt::region("PL").display_name(l),
                txt::currency("CHF").display_name(l), l.has_names());
    }
}
```

Output:

```text
polski: Polska | frank szwajcarski | true
Schweizer Hochdeutsch: Polen | Schweizer Franken | true
```
