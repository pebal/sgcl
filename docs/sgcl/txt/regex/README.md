# sgcl::txt::regex

```cpp
#include "sgcl/txt/regex.h"   // or "sgcl/txt.h"

namespace sgcl::txt {
    class regex;
}
```

**Requires [rooted](../../core/rooted/README.md) outside a stack or a managed object.**

`sgcl::txt::regex` is a compiled pattern in the style of RE2: everything a pattern can ask for here can be answered
in one pass over the text, and nothing else is offered. The time a match takes is the length of the text times the
length of the pattern, whatever the two are; there is no pattern and no text that costs more, and that is what the
class is for. A backreference, a lookaround, an atomic group, a conditional group and a possessive quantifier need
an engine that can go back and try again, and such an engine can be made to go back exponentially often: the
pattern refuses them by name, with the reason ([compile](compile.md#notes) gives the syntax, the refusals and
the limits).

The answers are leftmost-first, the ones Perl and Python give: the first branch of an alternation before the
second, a greedy quantifier taking what it can and a lazy one taking what it must. The machine is Pike's: every
alternative alive at once, in the order a backtracking engine would have tried them, so only the time is
different. Unlike `std::regex` there is no exponential case and no grammar to choose; unlike Go's `regexp`, whose
`MatchString` searches, [full_match](full_match.md) asks whether the whole text matches and
[contains](contains.md) whether some of it does.

The text is UTF-8 and the walk is over code points: `.` takes one character however many bytes it is written in,
`[а-я]` is a range of Cyrillic letters and not of bytes, `\w` is a letter in any script, and no word boundary falls
inside a character. The positions a [match](../match/README.md) reports are byte offsets, because a slice of a text is bytes
of it, and a match never begins or ends inside a character. Text that is not UTF-8 is read as Go's `regexp` reads
it: every byte of an ill-formed sequence is one U+FFFD, which `.` takes and a `U+FFFD` in the pattern matches.

## Rules

- A `regex` holds a `tracked_ptr` to its compiled program. A copy is one word and shares the program.
- Nothing in a `regex` changes after it is built, and each search keeps its own scratch: one `regex` may be used by
  any number of threads at once.
- A pattern written into the program is read where the program is compiled ([(constructor)](regex.md)), as
  the pattern of [format](../format.md) is: a pattern that cannot be one does not build. A pattern that arrives while
  the program runs goes through [compile](compile.md), which gives the `regex` or the reason in a
  [regex_error](../regex_error/README.md).
- There is no flags argument: a flag belongs in the pattern (`(?i)`, `(?m)`, `(?s)`), where whoever reads the
  pattern sees it, and it is spent where the program is built rather than branched on while the text is walked.
- Every member that takes a text takes a [string](../../core/string/README.md), a [slice\<const char\>](../../core/slice/README.md), an
  array of `char` (a literal among them) read up to its first NUL or its end, and a `const char*` or `char*` read up
  to its NUL; a `nullptr` does not compile. What a member hands back that holds the text — a [match](../match/README.md), the
  pieces of [split](split.md), the range of [all](all.md) — holds a C text as a copy in a string of its
  own.

### What it is held to

Python's `re` is the oracle, over **3000 random patterns** asked for their first match, **800** for every match and
**600** for the pieces a split leaves, generated by `tools/unicode_tables.py` beside the module's other test files.
Only what the two are defined to answer the same way is compared; where they differ by design
([compile](compile.md#where-this-parts-company-with-perl-and-python)) the pattern is translated in the
generator or the case is left out, and both differences are asserted directly in a test of their own. The
generator's own first run did not return, because a pattern drawn at random from three atoms and a quantifier sends
`re` into an exponential search every few hundred draws; every question put to the oracle is now given a quarter of
a second.

Beside that: eight patterns a backtracking engine goes exponential on, each with a **hard limit in milliseconds** in
the test rather than an argument about why it should be fast; and a fuzzer of 60000 rounds under the address and
undefined-behaviour sanitizers through every entry point, over texts with lone continuation bytes, a truncated
sequence, an encoded surrogate, a Tibetan `0F73`, a final sigma, a sharp s and a Kelvin sign.

## Complexity

A search is linear in the length of the text times the length of the pattern, for every pattern and every text.
Where every match must contain a run of bytes, the search skips to the places that run stands, by the same
Boyer–Moore–Horspool table [searcher](../searcher/README.md) uses or by `memchr` for a single byte; where there is no such run
it tests the bytes a match may begin with ([Benchmarks: regex](../benchmarks.md#regex)). Compiling is linear in the
length of the pattern once a `{n,m}` is spelled out into instructions.

## Example

```cpp
#include "sgcl/io.h"
#include "sgcl/txt.h"

using namespace sgcl;

int main() {
    txt::regex date("(?<y>\\d{4})-(?<m>\\d{2})-(?<d>\\d{2})");
    string text = "spotkanie 2026-09-23, a potem 2026-12-01";

    if (auto m = date.find(text)) {
        println("{}: rok {}", m->text(), *m->group("y"));
    }
    for (const auto& m : date.all(text)) {
        println("{}: {}", m.begin_at(), m.text());
    }
    println("{}", date.replace(text, "${d}.${m}.${y}"));

    for (auto piece : txt::regex("\\s*,\\s*").split(text)) {
        println("[{}]", piece);
    }
}
```

Output:

```text
2026-09-23: rok 2026
10: 2026-09-23
30: 2026-12-01
spotkanie 23.09.2026, a potem 01.12.2026
[spotkanie 2026-09-23]
[a potem 2026-12-01]
```
