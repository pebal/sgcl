# sgcl::crypto::p256

```cpp
#include "sgcl/crypto/p256.h"   // or "sgcl/crypto.h"

namespace sgcl::crypto::p256 {
    using public_key = /* unspecified */;
    using private_key = /* unspecified */;
    using ecdh_key = /* unspecified */;
}
```

`sgcl::crypto::p256` is the NIST curve P-256 (secp256r1, prime256v1; FIPS 186-5, SP 800-186 §3.2.1.3), Go's
`crypto/ecdsa` and `crypto/ecdh` over `elliptic.P256()`: the curve of TLS, of WebAuthn and passkeys, of JWS's ES256,
of most certificates signed with ECDSA. A [private_key](p256-private_key/README.md) signs digests ([ECDSA](ecdsa.md)), an
[ecdh_key](p256-ecdh_key/README.md) agrees on a shared secret (ECDH, SP 800-56A), and a [public_key](p256-public_key/README.md)
verifies signatures and is the other side's half of an agreement.

The three types are the same classes on [P-384](p384.md), with other sizes; their pages document both curves. Written
from FIPS 186-5, SEC 1 and RFC 6979; tested against RFC 6979's vectors, against OpenSSL (signatures both ways on
digests of every length, RFC 6979 nonces byte for byte, shared secrets, SEC 1 points accepted and refused alike,
PKCS #8, SEC 1 and SPKI both ways) and against Go (signatures, secrets and DER byte for byte), and fuzzed. **The
implementation has not been through an independent cryptographic audit.**

## Rules

- **One key, one purpose**, as in Go: a `private_key` is for ECDSA and an `ecdh_key` for key agreement.
  [to_ecdh](p256-private_key/to_ecdh.md) makes the one from the other for a protocol that needs both from one
  scalar; there is no way back.
- **Keys from data return `expected`**: `from_bytes`, `from_pkcs8_der`, `from_sec1_der`, `from_pem` and
  `from_pkix_der` give a [crypto::error](error/README.md) with `errc::invalid_key` for a scalar not in [1, n − 1] or a point
  that is not a point of the curve, `errc::malformed` (with the byte's offset) for DER or PEM that cannot be read,
  `errc::unsupported` for a key of another algorithm or curve or an encrypted one. `generate()` cannot fail.
- **A public key is checked when it is made**, so a `public_key` is always a valid point other than the identity, and
  ECDH with it cannot be led into a small subgroup (P-256 has none: its order is prime).
- **The private keys are secrets**: the scalar lives in the object (no allocation), the object is move-only,
  `clone()` makes a second one by name, a move zeroes the source and the destructor zeroes the scalar with stores the
  compiler cannot drop ([secure_zero](secure_zero.md)). Keep a key on the stack or in a `unique_ptr`: in a managed
  object it stays in memory until the cycle that finds it dead. The scalar and the shared secret come out as a
  [secret\<32\>](secret/README.md), the DER and PEM forms as a [secret_bytes](secret_bytes/README.md), never in managed memory. A
  key moved from is used by no operation: signing, `shared_secret`, `clone()`, `bytes()`, `public_key()`, `to_ecdh()`
  and the DER and PEM forms throw `std::logic_error`, as every key of the module does.
- **What is secret, and constant time**: the private scalar d, the per-signature scalar k and its inverse, the
  HMAC-DRBG state that makes k, and the shared secret go only through constant-time arithmetic and are zeroed when
  their scope ends. The field and the scalars are Montgomery arithmetic on four 64-bit words with no branch and no
  memory index that depends on a value; point addition is the complete formulas of Renes, Costello and Batina (no
  special case for the identity or for doubling); multiplication by a scalar takes each window's multiple by scanning
  the whole table through masks; the scalar inverse is Fermat's. A public key, a signature, a digest, the coordinates
  of k·G (r is public) and the parse of any encoding are not secret: decompressing a point, checking it is on the
  curve and verifying a signature may take time that depends on them. The outcome of a check on a secret (a
  candidate k out of range, a scalar of zero) is public too: it only makes the loop draw again.
- **Formats**: PKCS #8 (`PRIVATE KEY` in PEM) and SPKI (`PUBLIC KEY`) are written as Go's
  `x509.MarshalPKCS8PrivateKey` and `MarshalPKIXPublicKey` write them, and as OpenSSL does, byte for byte; SEC 1
  (`EC PRIVATE KEY`) as Go's `x509.MarshalECPrivateKey`, with the curve and the public key. Reading is strict DER; a
  SEC 1 scalar with a zero byte too many or too few is read as Go and OpenSSL read it. A public key's PEM is
  [encoding::pem](../encoding/pem/README.md)'s; a private key's is read and written by the key itself, straight into a
  `secret_bytes`.

## Member types

| Type | Definition |
|---|---|
| [public_key](p256-public_key/README.md) | a point of the curve: verifies signatures, the peer of an ECDH key; a value |
| [private_key](p256-private_key/README.md) | an ECDSA key: signs digests; move-only |
| [ecdh_key](p256-ecdh_key/README.md) | an ECDH key: agrees on a shared secret; move-only |

## Example

```cpp
#include "sgcl/crypto.h"
#include "sgcl/io.h"

using namespace sgcl;

int main() {
    // ECDSA: a key, a signature of a digest, its verification
    auto key = crypto::p256::private_key::generate();
    auto digest = crypto::sha256::of("the message");
    auto sig = key.sign_digest(digest);

    auto pub = key.public_key();
    println(pub.verify_digest(digest, sig) ? "valid" : "forged");
    println(pub.verify_digest(crypto::sha256::of("another message"), sig) ? "valid" : "forged");

    // ECDH: two parties agree on a secret, then derive a key from it
    auto alice = crypto::p256::ecdh_key::generate();
    auto bob = crypto::p256::ecdh_key::generate();
    auto a = alice.shared_secret(bob.public_key());
    auto b = bob.shared_secret(alice.public_key());
    if (a && b && crypto::constant_time::equal(a->bytes(), b->bytes())) {
        auto session = crypto::hkdf_sha256::derive("salt", a, "session key", 32);
        println(session.size() == 32 ? "agreed on a session key" : "no key");
    }
}
```

Output:

```text
valid
forged
agreed on a session key
```
