# sgcl::crypto::p384

```cpp
#include "sgcl/crypto/p384.h"   // or "sgcl/crypto.h"

namespace sgcl::crypto::p384 {
    using public_key = /* unspecified */;
    using private_key = /* unspecified */;
    using ecdh_key = /* unspecified */;
}
```

`sgcl::crypto::p384` is the NIST curve P-384 (secp384r1; FIPS 186-5, SP 800-186 §3.2.1.4), Go's `crypto/ecdsa` and
`crypto/ecdh` over `elliptic.P384()`: the curve of CNSA and of certificates that ask for 192 bits of security,
conventionally with SHA-384 (JWS's ES384, TLS's `ecdsa_secp384r1_sha384`).

The types and every rule are [p256](p256.md)'s — keys checked when made from data, one key per purpose, the private
keys move-only and zeroed, the shared secret the x-coordinate, constant time wherever a secret is, the same formats —
on six 64-bit words instead of four, so the sizes differ. The pages of the types document both curves. Tested as
P-256 is: RFC 6979's vectors (A.2.6), OpenSSL and Go both ways, fuzzing. **The implementation has not been through
an independent cryptographic audit.**

## Rules

- **The rules of [p256](p256.md#rules)**, all of them.
- **The sizes**, in bytes, where P-256's differ:

  | Size | P-384 | P-256 |
  |---|---|---|
  | a private scalar (`private_key::size`, `ecdh_key::size`, `bytes()`) | 48 | 32 |
  | a public key, uncompressed (`public_key::size`) | 97 | 65 |
  | a public key, compressed (`public_key::compressed_size`) | 49 | 33 |
  | a raw signature r ‖ s (`signature_size`) | 96 | 64 |
  | the longest DER signature (`private_key::max_signature_size`) | 104 | 72 |
  | the shared secret (`secret<N>`) | 48 | 32 |

  So `bytes()` of a private key and `shared_secret` give a `secret<48>`, `public_key::bytes()` an
  `array<byte, 97>`, `bytes_compressed()` an `array<byte, 49>` and `sign_digest_raw` an `array<byte, 96>`.
- **The hash of the nonce**: the hedged k of a signature is made by an HMAC-DRBG over SHA-384, where P-256's runs
  over SHA-256 ([ECDSA](ecdsa.md#rules)).
- **The types are not P-256's**: a `p384::public_key` is another type than a `p256::public_key`, and a key of one
  curve read as the other's is `errc::unsupported`.

## Member types

| Type | Definition |
|---|---|
| [public_key](p256-public_key.md) | a point of the curve: verifies signatures, the peer of an ECDH key; a value |
| [private_key](p256-private_key.md) | an ECDSA key: signs digests; move-only |
| [ecdh_key](p256-ecdh_key.md) | an ECDH key: agrees on a shared secret; move-only |

## Example

```cpp
#include "sgcl/crypto.h"
#include "sgcl/io.h"

using namespace sgcl;

int main() {
    auto key = crypto::p384::private_key::generate();
    auto digest = crypto::sha384::of("the message");
    auto sig = key.sign_digest(digest);
    println(key.public_key().verify_digest(digest, sig) ? "valid" : "forged");

    auto alice = crypto::p384::ecdh_key::generate();
    auto bob = crypto::p384::ecdh_key::generate();
    auto a = alice.shared_secret(bob.public_key());
    auto b = bob.shared_secret(alice.public_key());
    println(a && b && crypto::constant_time::equal(a->bytes(), b->bytes())
                ? "agreed" : "no agreement");
}
```

Output:

```text
valid
agreed
```
