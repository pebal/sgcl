# sgcl::crypto::p521

```cpp
#include "sgcl/crypto/p521.h"   // or "sgcl/crypto.h"

namespace sgcl::crypto::p521 {
    using public_key = /* unspecified */;
    using private_key = /* unspecified */;
    using ecdh_key = /* unspecified */;
}
```

`sgcl::crypto::p521` is the NIST curve P-521 (secp521r1; FIPS 186-5, SP 800-186 §3.2.1.5), Go's `crypto/ecdsa` and
`crypto/ecdh` over `elliptic.P521()`: the largest of the NIST curves, 256 bits of security, conventionally with
SHA-512 (JWS's ES512, TLS's `ecdsa_secp521r1_sha512`, SSH's `ecdsa-sha2-nistp521`).

The types and every rule are [p256](p256.md)'s — keys checked when made from data, one key per purpose, the private
keys move-only and zeroed, the shared secret the x-coordinate, constant time wherever a secret is, the same formats —
on nine 64-bit words, of which 521 bits are used, so the sizes differ: a coordinate and a scalar are 66 bytes. The
field is the Mersenne prime 2^521 - 1, whose products are reduced by folding their high bits onto their low ones
rather than by Montgomery's reduction. The pages of the types document the three curves. Tested as P-256 is: RFC
6979's vectors (A.2.7), Wycheproof's, OpenSSL and Go both ways, fuzzing. **The implementation has not been through an
independent cryptographic audit.**

## Rules

- **The rules of [p256](p256.md#rules)**, all of them.
- **The sizes**, in bytes, where P-256's differ:

  | Size | P-521 | P-256 |
  |---|---|---|
  | a private scalar (`private_key::size`, `ecdh_key::size`, `bytes()`) | 66 | 32 |
  | a public key, uncompressed (`public_key::size`) | 133 | 65 |
  | a public key, compressed (`public_key::compressed_size`) | 67 | 33 |
  | a raw signature r ‖ s (`signature_size`) | 132 | 64 |
  | the longest DER signature (`private_key::max_signature_size`) | 140 | 72 |
  | the shared secret (`secret<N>`) | 66 | 32 |

  So `bytes()` of a private key and `shared_secret` give a `secret<66>`, `public_key::bytes()` an
  `array<byte, 133>`, `bytes_compressed()` an `array<byte, 67>` and `sign_digest_raw` an `array<byte, 132>`.
- **A digest's leftmost 521 bits**: ECDSA takes as many bits of a digest as the order has. SHA-512's 64 bytes are
  taken whole; a digest of 66 bytes or more is cut to its leftmost 521 bits, so its last 7 bits of the 66th byte, and
  everything after, count for nothing ([ECDSA](ecdsa.md#rules)).
- **The hash of the nonce**: the hedged k of a signature is made by an HMAC-DRBG over SHA-512.
- **The types are not P-256's**: a `p521::public_key` is another type than a `p256::public_key`, and a key of one
  curve read as the other's is `errc::unsupported`.

## Member types

| Type | Definition |

| [public_key](p256-public_key/README.md) | a point of the curve: verifies signatures, the peer of an ECDH key; a value |

## Example

```cpp
#include "sgcl/crypto.h"
#include "sgcl/io.h"

using namespace sgcl;

int main() {
    auto key = crypto::p521::private_key::generate();
    auto digest = crypto::sha512::of("the message");
    auto sig = key.sign_digest(digest);
    println(key.public_key().verify_digest(digest, sig) ? "valid" : "forged");

    auto alice = crypto::p521::ecdh_key::generate();
    auto bob = crypto::p521::ecdh_key::generate();
    auto a = alice.shared_secret(bob.public_key());
    auto b = bob.shared_secret(alice.public_key());
    println(a && b && crypto::constant_time::equal(a->bytes(), b->bytes())
                ? "agreed" : "no agreement");
    println("{}", crypto::p521::public_key::size);
}
```

Output:

```text
valid
agreed
133
```
