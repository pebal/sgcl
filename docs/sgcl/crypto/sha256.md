# sgcl::crypto::sha256

```cpp
#include "sgcl/crypto/sha256.h"   // or "sgcl/crypto.h"

namespace sgcl::crypto {
    class sha256;
    class sha224;
}
```

`sgcl::crypto::sha256` is SHA-256 of FIPS 180-4, Go's `crypto/sha256`: the digest of TLS, of certificates, of code
signatures and of most of what signs or names anything by its contents today. `sha224` is SHA-224, the same
function from other initial values, cut to 28 bytes: its `digest_size` is 28 and its `value()` an `array<byte, 28>`,
and everything else is as for `sha256`. Both are written from FIPS 180-4; the tests hold them against the standard's
examples and against OpenSSL on random data of every length to 1024 and beyond, fed at once and in pieces.

Where Go's `sha256.New()` is a `hash.Hash` behind an interface and `Sum(b)` appends to a slice, a `sha256` is a plain
value with the shape of every hasher of the [hash module](../hash/README.md): `update` takes bytes and text,
`value()` is the digest as an `array<byte, 32>` and the hasher goes on, and a copy is Go's `Clone`.

**The implementation has not been through an independent cryptographic audit.**

## Rules

- **The shape of a hasher** of the [hash module](../hash/README.md): `update` takes bytes (`slice<const byte>`, a
  `vector<byte>`, an `array<byte, N>`, a `std::span` of bytes) and text (a `string`, a literal, a `std::string_view`,
  a C string), `value()` is the digest and ends nothing, `digest()` is the same bytes, `reset()` is as new, `of(data)`
  is the one-shot form, `copy_from(reader)` reads a stream to its end. A `crypto::sha256` goes wherever a
  `hash::req::hasher` is asked for.
- **A copy is a branch**, Go's `Clone`: a common prefix hashed once, then two ways. A hasher is the eight chaining
  words, a block's buffer and the length, about 110 bytes, trivially copyable and nothing for the collector, so it
  lives anywhere a plain struct does. Its state is not zeroed when it dies: the keyed form that zeroes is
  [hmac](hmac.md).
- **Not a MAC.** A digest of a secret and a message is open to length extension; a tag is [hmac\<sha256\>](hmac.md).
  SHA-224 cut to 28 bytes is not much safer in that respect: it drops only 4 bytes.
- **Not for passwords**: a digest is fast by design, and a password needs a slow function ([pbkdf2](pbkdf2.md), or
  Argon2id and scrypt after version 1).
- **Hashing never fails and never waits**: `update`, `value`, `digest`, `reset` and `of` are `noexcept`; only the
  mixin's `copy_from` and `of_file` wait, for a stream or a file, and return its error. One object is one thread's at
  a time, as any value.

## Complexity

Linear in the bytes hashed, one compression a block of 64. On arm64 the blocks go through the SHA-256 instructions of
ARMv8 (`SHA256H`, `SHA256H2`, `SHA256SU0`, `SHA256SU1`), four steps an instruction pair, the state in two registers.
The path is compiled for every little-endian arm64 target and chosen at run time from what the processor reports
(`hw.optional.arm.FEAT_SHA256` on macOS, `HWCAP_SHA2` on Linux) — at compile time, with no question asked, where the
target promises the feature, as the default target of macOS does. Elsewhere, and with `SGCL_CRYPTO_PORTABLE` defined,
the compression is plain C++; the tests run every vector on both paths and hold the two against each other block by
block. A program is built with one setting of the macro throughout.

## Example

```cpp
#include "sgcl/crypto.h"
#include "sgcl/encoding.h"
#include "sgcl/io.h"

using namespace sgcl;

int main() {
    println(encoding::hex::encode(crypto::sha256::of("abc")));

    // in pieces, the same digest
    crypto::sha256 h;
    h.update("a");
    h.update("bc");
    println(encoding::hex::encode(h.value()));

    println(encoding::hex::encode(crypto::sha224::of("abc")));
}
```
