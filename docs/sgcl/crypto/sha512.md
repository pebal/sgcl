# sgcl::crypto::sha512

```cpp
#include "sgcl/crypto/sha512.h"   // or "sgcl/crypto.h"

namespace sgcl::crypto {
    class sha512;
    class sha384;
    class sha512_256;
}
```

`sgcl::crypto::sha512` is SHA-512 of FIPS 180-4, Go's `crypto/sha512`: the SHA-2 digest on words of 64 bits,
Ed25519's digest and a common choice for HMAC and PBKDF2. Two more stand beside it, the same function from other
initial values, cut: `sha384`, 48 bytes, TLS 1.3's `TLS_AES_256_GCM_SHA384` and P-384's digest, and `sha512_256`,
SHA-512/256, 32 bytes at SHA-512's speed. Being cut, neither is open to length extension. Their `digest_size` is 48
and 32 and their `value()` an `array<byte, 48>` and an `array<byte, 32>`; everything else is as for `sha512`. Written
from FIPS 180-4, tested against its examples and against OpenSSL.

The three have the shape of every hasher of the [hash module](../hash/README.md), as [sha256](sha256.md) has it:
`update` takes bytes and text, `value()` is the digest and the hasher goes on, and a copy is Go's `Clone`.

**The implementation has not been through an independent cryptographic audit.**

## Rules

- **The shape of a hasher** of the [hash module](../hash/README.md), as [sha256](sha256.md) has it: `update`,
  `value()`, `digest()`, `reset()`, `of`, `copy_from`. Each goes wherever a `hash::req::hasher` is asked for.
- **A copy is a branch.** A hasher is about 210 bytes (eight words of 64 bits, a block of 128 bytes, the length),
  trivially copyable and nothing for the collector, so it lives anywhere a plain struct does. Its state is not zeroed
  when it dies.
- **The length** is counted in bytes in 64 bits: up to 2^64 bytes a message, where the standard allows 2^128 bits.
- **Not a MAC** standing alone for `sha512` (a tag is [hmac_sha512](hmac.md)), and **not for passwords**
  ([pbkdf2](pbkdf2.md)).
- **Hashing never fails and never waits**: `update`, `value`, `digest`, `reset` and `of` are `noexcept`; only the
  mixin's `copy_from` and `of_file` wait, for a stream or a file, and return its error.

## Complexity

Linear in the bytes hashed, one compression a block of 128. SHA-512 is faster than SHA-256 per byte on a processor
with no SHA instructions (64-bit words, 128-byte blocks) and slower on one with both sets, as Apple silicon is; choose
by the protocol, not by speed.

On arm64 the blocks go through the SHA-512 instructions of ARMv8.2 (`SHA512H`, `SHA512H2`, `SHA512SU0`, `SHA512SU1`),
two steps an instruction pair, the state in five registers whose names rotate. The processor is asked for
`FEAT_SHA512` (`HWCAP_SHA512`), apart from SHA-3's feature: the architecture makes them two options. Elsewhere, and
with `SGCL_CRYPTO_PORTABLE`, the compression is plain C++; both paths run every vector in the tests.

## Example

```cpp
#include "sgcl/crypto.h"
#include "sgcl/encoding.h"
#include "sgcl/io.h"

using namespace sgcl;

int main() {
    println(encoding::hex::encode(crypto::sha512::of("abc")));
    println(encoding::hex::encode(crypto::sha384::of("abc")));
    println(encoding::hex::encode(crypto::sha512_256::of("abc")));
}
```
