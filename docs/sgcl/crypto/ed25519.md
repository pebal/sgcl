# sgcl::crypto::ed25519

```cpp
#include "sgcl/crypto/ed25519.h"   // or "sgcl/crypto/crypto.h"

namespace sgcl::crypto::ed25519 {
    class private_key;   // a seed of 32 secret bytes and what it gives; move-only
    class public_key;    // a point of the curve, 32 bytes; a value

    inline constexpr size_t public_key_size = 32;
    inline constexpr size_t private_key_size = 64;   // the seed and the public key, as Go's PrivateKey
    inline constexpr size_t seed_size = 32;
    inline constexpr size_t signature_size = 64;
}
```

Ed25519 (RFC 8032 §5.1), Go's `crypto/ed25519`: signatures of 64 bytes under keys of 32. The scheme is deterministic — the same key and message give the same signature, and signing needs no random numbers — and it is the signature of SSH keys, of TLS 1.3 certificates, of package managers and of JWTs (EdDSA). Pure Ed25519 only: the message is signed as it is (Ed25519ph and Ed25519ctx are not here, as they are not in Go's default). Written from RFC 8032, tested against its vectors (TEST 1, 2, 3, 1024 and SHA(abc)), against OpenSSL on messages of every length 0–1024 and a few large ones (the same signatures, each verifying the other's), against Go's `crypto/ed25519` on two thousand random keys and the SUPERCOP vectors of Go's tree, and on the edge cases of verification against Go and against a slow reference on big integers.

**The implementation has not been through an independent cryptographic audit.**

## Rules

- **A private key is a seed** of 32 random bytes (`generate()` takes them from [`random`](random.md)); SHA-512 of the seed gives the secret scalar and the prefix the nonces come from, and the public key. `from_seed` takes the 32 bytes, `from_private_bytes` the 64 of Go's `PrivateKey` and of `bytes()` — the seed and the public key, whose public half must be the seed's (`errc::invalid_key` otherwise: signing under a mismatched pair would give the key away). A key of the wrong length is `errc::invalid_key`.
- **Verification is Go's and RFC 8032's**: S must be below the group order L; the public key must be the canonical encoding of a point on the curve — `from_bytes` refuses a y of p or more and an x of 0 with the sign bit set, as RFC 8032 §5.1.3 decodes, where Go takes such a key reduced; R is compared as bytes with the encoding of [S]B − [k]A, so a non-canonical R never matches; and the equation is the one without the cofactor. Keys of small order are not refused, as neither the RFC nor Go refuses them: under such a key a signature can be had for nothing, so a protocol that must bind a signature to one signer checks the key where it is registered.
- **`verify` is `[[nodiscard]]`**: a check whose result is dropped was never made. A signature of another length than 64 is false.
- **Messages are bytes or text**: `sign("text")` signs the text's bytes, as `sign(bytes)` does.
- **Constant time where it matters.** Signing computes r·B for the secret nonce r by a fixed-base multiplication whose table is read whole with masks, and S = r + k·s mod L by arithmetic with no branch on the values; the field arithmetic has no branch and no memory index that depends on a value. What is secret: the seed, the scalar, the prefix, each signature's nonce. What is not: the public key, the message, the signature and everything the verification computes — the verification takes branches on them, as every implementation's does.
- **A secret, so no copy.** `private_key` holds the seed, the scalar and the prefix in the object's own memory; it is move-only, `clone()` makes a second one, a move leaves the object moved from zeroed, and the destructor zeroes it with stores the compiler cannot drop ([`secure_zero`](secure_zero.md)). Keep a key on the stack or in a `unique_ptr`: in a managed object it stays in memory until the cycle that finds it dead. `seed()` and `bytes()` return a [`secret<32>`](secret.md) and a `secret<64>`, which zero themselves in turn; `to_pkcs8_der()` returns a managed `vector<byte>` that holds the seed.
- **Where it differs from Go and OpenSSL, deliberately.** Two things, both stricter:
  - *A non-canonical public key is refused.* An encoding of y = p or more (`ed…ff7f`, `ee…ff7f`) and an x of 0 with the sign bit set (the "negative zero") are not points by RFC 8032 §5.1.3 ("if the resulting value is ≥ p, decoding fails"); Go and OpenSSL reduce them and accept the signatures under them. Of the tests' edge cases these two are the only ones where the verdicts differ, and the test lists them as the expected differences. Accepting them serves only consensus between implementations (ZIP 215), which TLS and X.509 do not need.
  - *`from_private_bytes` checks the public half* against the seed, at the cost of one scalar multiplication; Go takes the 64 bytes as they are. A pair put together from two sources would sign under someone else's public key, and signatures under a mismatched pair give the secret scalar away.
- **Keys in files**: `to_pkcs8_der` / `from_pkcs8_der` (PKCS #8, RFC 8410, OID 1.3.101.112, the seed inside) and `to_pkix_der` / `from_pkix_der` (SubjectPublicKeyInfo), byte for byte as OpenSSL writes them. Reading is strict DER; a version 1 PKCS #8 may carry the public key, which must be the seed's, and attributes, which are skipped; another algorithm's key is `errc::unsupported`, broken DER `errc::malformed` with the offset. PEM goes through [`encoding::pem`](../encoding/pem.md).

## Members

```cpp
class private_key {
public:
    static private_key generate();
    static expected<private_key, error> from_seed(const slice<const byte>& seed);           // 32 bytes
    static expected<private_key, error> from_private_bytes(const slice<const byte>& bytes); // 64 bytes
    static expected<private_key, error> from_pkcs8_der(const slice<const byte>& der);

    private_key(private_key&& other) noexcept;             // other zeroed
    private_key& operator=(private_key&& other) noexcept;
    private_key(const private_key&) = delete;
    ~private_key();                                        // zeroed
    private_key clone() const noexcept;

    ed25519::public_key public_key() const noexcept;       // computed once, when the key is made
    secret<32> seed() const noexcept;
    secret<64> bytes() const noexcept;                     // the seed and the public key
    array<byte, 64> sign(const slice<const byte>& message) const noexcept;               // bytes or text
    vector<byte> to_pkcs8_der() const;                     // 48 bytes
    friend bool operator==(const private_key& a, const private_key& b) noexcept;   // constant time
};

class public_key {
public:
    static expected<public_key, error> from_bytes(const slice<const byte>& bytes);  // 32 bytes, a canonical point
    static expected<public_key, error> from_pkix_der(const slice<const byte>& der);
    const array<byte, 32>& bytes() const noexcept;
    [[nodiscard]] bool verify(const slice<const byte>& message, const slice<const byte>& signature) const noexcept;
    vector<byte> to_pkix_der() const;                      // 44 bytes
    friend bool operator==(const public_key& a, const public_key& b) noexcept;
};
```

## Example

```cpp
#include "sgcl/crypto/ed25519.h"
#include "sgcl/encoding/hex.h"
#include "sgcl/io/print.h"

using namespace sgcl;

int main() {
    // a key from a seed of 32 bytes (RFC 8032's TEST 1); a program makes
    // its own with generate() and keeps the seed secret
    auto key = crypto::ed25519::private_key::from_seed(
        encoding::hex::decode("9d61b19deffd5a60ba844af492ec2cc44449c5697b326919703bac031cae7f60"));
    auto public_key = key->public_key();
    println("public key: {}", encoding::hex::encode(public_key.bytes()));

    auto signature = key->sign("release 1.4.2");
    println("signature: {}...", encoding::hex::encode(signature).substr(0, 32));

    // the receiver has the public key's bytes, the message and the signature
    auto received = crypto::ed25519::public_key::from_bytes(public_key.bytes());
    println(received->verify("release 1.4.2", signature) ? "valid" : "forged");
    println(received->verify("release 1.4.3", signature) ? "valid" : "forged");

    // the key in the forms other programs read: PKCS #8 and SubjectPublicKeyInfo
    auto der = public_key.to_pkix_der();
    println("SubjectPublicKeyInfo: {} bytes", der.size());
    auto back = crypto::ed25519::public_key::from_pkix_der(der);
    println(back == public_key ? "the same key" : "another key");
}
```
