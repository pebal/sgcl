# sgcl::crypto::x509::certificate::permitted_dns_domains, excluded_dns_domains

```cpp
/*(1)*/ const vector<string>& permitted_dns_domains() const noexcept;
/*(2)*/ const vector<string>& excluded_dns_domains() const noexcept;
```

Return the DNS subtrees of the nameConstraints:

1. the permitted ones;
2. the excluded ones.

A subtree `example.com` covers `example.com` and every name below it, `www.example.com`; `.example.com` only the names
below it. A wildcard name is excluded when it could match an excluded subtree. A `dNSName` of a certificate with a
trailing dot cannot be checked under a CA with name constraints, and fails.

A CA's name constraints (RFC 5280 §4.2.1.10, checked by Go's rules) apply to every name of every certificate below
it, intermediates' too. A permitted list of a kind lets through only what one of its entries covers, an excluded one
stops what any covers, and a kind no list names passes.

## Parameters

None.

## Return value

The subtrees, in the order of the certificate; empty when there are none of the kind.

## Complexity

Constant.

## Exceptions

None.
