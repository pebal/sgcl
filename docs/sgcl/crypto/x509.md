# sgcl::crypto::x509

```cpp
#include "sgcl/crypto/x509.h"   // or "sgcl/crypto/crypto.h"

namespace sgcl::crypto::x509 {
    class certificate;          // read from DER or PEM; verify(), verify_hostname(), verify_ip()
    class certificate_pool;     // roots or intermediates; system()
    struct verify_options;      // roots, intermediates, dns_name, ip, time, key_usages
    using chain = vector<certificate>;
    class name;                 // an issuer or a subject: attributes, to_string()
    class public_key;           // rsa, p256, p384, ed25519 or none
    struct ip_address;          // 4 or 16 bytes
    struct ip_range;            // an address and a mask (name constraints)
    struct extension;           // oid, critical, value
    enum class reason;          // why a chain does not verify
    enum class key_usage;  enum class ext_key_usage;  enum class signature_algorithm;  enum class key_kind;
}
```

X.509 certificates (RFC 5280), Go's `crypto/x509`: a certificate read from DER or PEM with its names, its key and its extensions, a pool of certificates, and the verification of a chain from a leaf through intermediates to a trusted root, with the DNS name or the IP address the leaf must be for. What TLS needs to decide whether a server is the one it claims to be; what code signing, S/MIME and mutual TLS need to know who signed. Written from RFC 5280, RFC 6125 and X.690; tested field by field against Go's parser on 517 certificates (Go's test tables and testdata, the system's bundle), against Go's own verdicts on every case of its `verify_test.go` and `name_constraints_test.go`, against OpenSSL's `X509_verify_cert` (verdict and reason) on chains of every algorithm made by OpenSSL in the tests, and fuzzed with OpenSSL as the oracle of what DER is.

**The implementation has not been through an independent cryptographic audit.**

## Rules

- **Reading.** `certificate::parse(der)` and `certificate::from_pem(text)` (the first `CERTIFICATE` block that reads, whatever is around it: the blocks are read one by one, and one that cannot be read as PEM or is of another type is passed over, before the certificate or after it) return `expected<certificate, error>`: `errc::malformed` with the offset of the byte for anything that is not a certificate in **strict DER** — lengths in their shortest form, no indefinite length, no string cut in pieces, a BOOLEAN of `00` or `FF`, integers and OIDs in their shortest form, nothing after the last field of a structure, the times only as `YYMMDDHHMMSSZ` (UTCTime, 1950 to 2049) and `YYYYMMDDHHMMSSZ` (GeneralizedTime) with every field in range, a version 1 or 2 certificate without extensions, no extension twice. A few encodings DER forbids are read as Go and OpenSSL read them (listed under *Where it differs*). A certificate this module reads is one OpenSSL reads too (the fuzzer holds it to that); a few that Go and OpenSSL read are refused as not DER.
- **Bounds** (§11 A7 of the design): a certificate of at most 128 KiB (checked before anything is copied), 64 extensions, 1024 names in its SAN, 256 subtrees of name constraints, 64 extended key usages, 64 policies, 64 attributes in a name, sixteen levels of nesting; past any of them, `errc::malformed`. Real certificates stay far below.
- **The key.** `public_key()` is one of the module's key types — `rsa::public_key`, `p256::public_key`, `p384::public_key`, `ed25519::public_key` — by `kind()`, or `key_kind::none` for an algorithm the module has no type for (DSA, X25519, P-521, ML-DSA) or a key its type refuses (RSA under 1024 bits), or an EC key whose parameters are explicit or NULL rather than a named curve; the certificate is still read, as Go reads one of an unknown algorithm, and `public_key().algorithm()` names the algorithm's OID. A certificate signed by such a key does not verify (`unsupported_algorithm`).
- **The names.** `subject()` and `issuer()` are `name`s: every attribute in order (its OID and its value; text for the six string types, UTF-8 whatever the encoding was, else `#` and the hex of the DER), the common ones by name (`common_name()`, `organization()`, `country()`, …), and `to_string()` as Go's `pkix.Name.String()` writes it (`CN=www.example.com,O=Example\, Inc.`). A chain is built by the bytes of the names (`raw_issuer()` of the child equal to `raw_subject()` of the parent), as Go builds it.
- **Verification** (`verify(options)`, Go's `Verify`): a chain from the leaf through `intermediates` to a certificate of `roots` (the system's when none is given) — the parents a pool has for the issuer's name, roots before intermediates, depth first; the key identifiers only order them (a parent whose `subjectKeyIdentifier` is the child's `authorityKeyIdentifier` is tried first, one whose is not is still tried); **at most ten intermediates**, no certificate twice (a loop of cross-signatures ends), at most a hundred signatures tried (Go's budget: on a hostile pool of RSA-16384 keys about a second). Each signature checked: RSA PKCS #1 v1.5 and PSS (MGF1 over the same hash, the salt as long as the hash — the three sets of parameters Go takes — and the signature's salt exactly that long, as Go and OpenSSL check it), ECDSA on P-256 and P-384, Ed25519; over SHA-256, SHA-384 and SHA-512. **MD5 and SHA-1 are never accepted** (`insecure_algorithm`), as Go has them since 1.18; a root's own signature is never checked (it is trusted as it is). Each certificate valid at `time` (both ends included, as RFC 5280 §4.1.2.5 has it); each issuer a CA (a version 3 certificate needs `basicConstraints` with cA; its `keyUsage`, where there is one, needs `keyCertSign`); each `pathLenConstraint` kept (a self-issued intermediate, whose issuer and subject are the same name, not counted: RFC 5280 §4.2.1.9); no critical extension this module does not handle; the name constraints of every CA over every name below it; the extended key usages nested down the chain. The first chain that passes is returned, leaf first and root last.
- **Why it failed**: an error with `code() == errc::verification` and `reason()`, one of the `reason` values below, with the certificate at fault in its `message()`. When no chain is found, the reason is, at each level, the one of the first parent whose signature over the child verified, as deep as it went (an expired intermediate is `expired`, not "unknown authority"); only when no parent's signature verified, the first of those failures (`invalid_signature`, `not_a_ca`, `missing_cert_sign`, an algorithm); `unknown_authority` when the pools hold no parent of the issuer's name — so a root rolled over to a new key, the old one in the pool and tried first, does not hide why the path through the new key failed. A chain that reached a root but broke a name constraint or a key usage says so. Compare `reason()`, not errors: `error`'s `==` compares the message too, so `r.error() == error(reason::expired, "")` is never true.
- **Host names** (RFC 6125 §6.4, as Go matches them): `dns_name` (or `verify_hostname`) against the leaf's DNS names only — **the common name never**, as Go since 1.15 and browsers; ASCII case folded; a trailing `.` of the name asked ignored; a wildcard only as the **whole leftmost label** (`*.example.com`), matching exactly one label: not `example.com`, not `a.b.example.com`, and `f*.example.com` is no wildcard at all. A name written as an IPv4 or IPv6 address is refused as a DNS name (RFC 6125 Appendix B.2): addresses are verified by their bytes.
- **IP addresses are bytes.** `ip_addresses()` gives `ip_address` values (`bytes`, `size` of 4 or 16), and `verify_options::ip` or `verify_ip()` take 4 or 16 bytes in network order, compared byte for byte (RFC 5280 §4.2.1.6), a 16-byte IPv4-mapped address (`::ffff:a.b.c.d`) taken as its IPv4 address, in the options and in a certificate's SAN alike (`ip_addresses()` gives such an entry as 4 bytes); another length is `std::invalid_argument` (the address is the program's). The crypto module parses no address text and does not depend on `net`: `net::ip_address::bytes()` gives the bytes, and `net::tls` will convert.
- **Name constraints** (RFC 5280 §4.2.1.10, Go's rules): DNS names, IP ranges (`address & mask`), email addresses (a mailbox or a domain) and the domains of URIs, permitted and excluded; a permitted list of a kind lets through only what one of its entries covers (`example.com` covers `example.com` and `www.example.com`, `.example.com` only names below it), an excluded one stops what any covers, a wildcard name included when it could match an excluded one; a kind no list names passes. They apply to every name of every certificate below the CA that has them, intermediates' too. Directory names are not constrained: a critical extension with such a subtree is unhandled, and the constraints do not reach the subject's distinguished name.
- **Extended key usage**: `key_usages` in the options, `server_auth` when empty, `ext_key_usage::any` for no check. Walking down from the root, a certificate that lists usages (and not `any`) crosses out every usage asked it does not list; the chain passes while one is left. `keyUsage` of the leaf is not checked (Go does not either); a CA's `keyCertSign` is.
- **Time**: `verify_options::time`, the time now when not given (`time::now()`, which a test's manual clock moves). `not_before()` and `not_after()` are `time::datetime`s in UTC; a certificate's time outside datetime's years (the common `99991231235959Z`, "no expiry") is the end of that range there, while verification compares the time as the certificate has it.
- **Not here: revocation.** No CRL, no OCSP, no certificate transparency: a revoked certificate verifies until it expires. **Not here: policy validation.** `policies()` gives the OIDs of `certificatePolicies`; a critical `policyConstraints`, `policyMappings` or `inhibitAnyPolicy` is an unhandled critical extension, so that a chain whose CA asks for policy processing fails rather than passes unchecked (Go validates policies; the roots of the system's bundle have none of these).
- **Pools** are handles, as Go's `*CertPool`: a copy shares the certificates, `add` through one is seen through every copy, `clone()` makes one of its own. Reading from several threads at once is safe; adding while another thread verifies is not. `certificate_pool::system()` is the system's roots, read once per process and cloned for every call: the file `SSL_CERT_FILE` names, else the first bundle of Go's list (`/etc/ssl/certs/ca-certificates.crt`, `/etc/pki/tls/certs/ca-bundle.crt`, `/etc/ssl/ca-bundle.pem`, `/etc/pki/tls/cacert.pem`, `/etc/pki/ca-trust/extracted/pem/tls-ca-bundle.pem`, `/etc/ssl/cert.pem` — the last is macOS's), else the files of `SSL_CERT_DIR` or `/etc/ssl/certs` and `/etc/pki/tls/certs`; `errc::unsupported` when none holds a certificate. `async_system()` reads the files on the blocking pool, for a task. `from_file(path)` is a pool of the certificates of one PEM file (`async_from_file` on the blocking pool), `expected<certificate_pool, io::error>`: the file system's error as `io`'s (`is_not_found()` for a file that is not there), the blocks read as `append_pem` reads them. `from_pem` and `append_pem` add every `CERTIFICATE` block that parses and pass over the rest (other types, blocks with RFC 1421 headers, blocks that do not read), as Go's `AppendCertsFromPEM`; after a block that does not read, the text is read on from the line after its BEGIN, so that a BEGIN without an END of its own does not take the next block with it.
- **Never an exception from data.** A certificate, however broken, is `errc::malformed` from `parse` or a verification error from `verify`; signatures are checked with the forms that return `false` (§11 A2), never throwing: a certificate cannot stop the program. The certificate is a value: its parse is shared by its copies, and it lives where a `tracked_ptr` may.

## Why a chain does not verify

| `reason` | what | Go | OpenSSL |
|---|---|---|---|
| `expired`, `not_yet_valid` | a certificate of the chain outside its validity at `time` | `Expired` | `CERT_HAS_EXPIRED`, `CERT_NOT_YET_VALID` |
| `unknown_authority` | no chain leads to a root of the pool | `UnknownAuthorityError` | `UNABLE_TO_GET_ISSUER_CERT_LOCALLY` |
| `hostname_mismatch` | the leaf is not for the DNS name or the IP address asked | `HostnameError` | `HOSTNAME_MISMATCH`, `IP_ADDRESS_MISMATCH` |
| `name_constraints` | a name outside a CA's name constraints, or one that cannot be checked | `CANotAuthorizedForThisName` | `PERMITTED_VIOLATION`, `EXCLUDED_VIOLATION` |
| `unsupported_algorithm` | a signature or an issuer's key of an algorithm not verified here | `ErrUnsupportedAlgorithm` | — |
| `insecure_algorithm` | a signature over MD2, MD5 or SHA-1 | `InsecureAlgorithmError` | `CA_MD_TOO_WEAK` |
| `invalid_signature` | a signature that does not verify under its issuer's key | (a hint of `UnknownAuthorityError`) | `CERT_SIGNATURE_FAILURE` |
| `too_many_intermediates` | more than ten intermediates, or more than a hundred signatures tried | — | `CERT_CHAIN_TOO_LONG` |
| `path_length` | a CA's `pathLenConstraint` exceeded | `TooManyIntermediates` | `PATH_LENGTH_EXCEEDED` |
| `not_a_ca` | an issuer without `basicConstraints` cA | `NotAuthorizedToSign` | `INVALID_CA` |
| `missing_cert_sign` | an issuer whose `keyUsage` lacks `keyCertSign` | (a hint) | `INVALID_CA` |
| `incompatible_usage` | no extended key usage asked is allowed by the whole chain | `IncompatibleUsage` | `INVALID_PURPOSE` |
| `unhandled_critical_extension` | a critical extension not handled here | `UnhandledCriticalExtension` | `UNHANDLED_CRITICAL_EXTENSION` |
| `too_many_constraints` | name constraints that would take more than a million comparisons | `TooManyConstraints` | — |

`reason()` is `none` for an error that is not `errc::verification`: the system's roots missing (`errc::unsupported`), a certificate that does not parse (`errc::malformed`).

## Where it differs

Where this module and OpenSSL answer differently, it is mostly Go's answer (the tests hold both):

- The last second of `not_after` is valid (OpenSSL ends the period there).
- `anyExtendedKeyUsage` in a CA allows every usage (OpenSSL's `ssl_server` purpose wants `serverAuth` there).
- An issuer whose first path fails is tried again through another (OpenSSL takes the first issuer it finds).
- A wildcard DNS name that could match an excluded name is excluded.
- The key identifiers are a hint, not a requirement, as in Go: a parent whose `subjectKeyIdentifier` differs from the child's `authorityKeyIdentifier` is still tried (OpenSSL does not take it as the issuer, and says it found none).
- A self-issued intermediate (the same name as issuer and subject: a cross-signature of a root's new key by its old one) does not count against a `pathLenConstraint`, as RFC 5280 and OpenSSL have it; Go counts it.
- A version 3 root without `basicConstraints` cannot sign, even with a `keyUsage` of `keyCertSign`: `not_a_ca`, as in Go (OpenSSL takes it as a trust anchor).
- A trust anchor need not be self-signed: any certificate of `roots` ends a chain, its own signature never checked (OpenSSL wants `X509_V_FLAG_PARTIAL_CHAIN` for one that is not).
- A `dNSName` of a certificate with a trailing dot is read and matched only exactly, as Go matches it; under a CA with name constraints it cannot be checked, and fails.
- A SAN URI with no host, or with an IP address as its host, fails under every CA with name constraints, as in Go 1.27 (RFC 5280 and OpenSSL fail it only under a CA with a URI subtree).
- An IPv4-mapped address in a certificate's SAN is its IPv4 address, IPv4 ranges of the name constraints applying to it (Go keeps the 16 bytes and compares them with IPv6 ranges).
- Three values DER wants left out as their DEFAULT are read when written — `version [0]` of v1, an extension's `critical` FALSE, `basicConstraints`' cA FALSE — and so is a `keyUsage` BIT STRING with trailing zero bits, as Go and OpenSSL read them; this module does not catch them.
- A `SubjectPublicKeyInfo` whose BIT STRING has unused bits is `malformed` for a key of the module's algorithms, and read with `key_kind::none` for any other.
- A critical `subjectKeyIdentifier`, `authorityKeyIdentifier` or `authorityInfoAccess` is `malformed` (RFC 5280 has them non-critical).
- A host asked with a trailing dot (`example.com.`) is the name without it, as in Go. The host is compared in ASCII: an internationalized name is asked in A-labels (`xn--…`), which `txt::idna::to_ascii` gives ([`idna`](../txt/idna.md)).
- `name`'s `==` compares the attributes as text (a PrintableString and a UTF8String of the same characters are equal), while a chain is built on the bytes of the names.

class certificate {                                  // a value; copies share the parse

    [[nodiscard]] static expected<certificate, error> parse(const slice<const byte>& der);
    [[nodiscard]] static expected<certificate, error> from_pem(const string& text);   // the first CERTIFICATE block

    slice<const byte> raw() const noexcept;                                  // the whole DER
    slice<const byte> raw_tbs() const noexcept;                              // what the signature covers

    slice<const byte> raw_subject_public_key_info() const noexcept;

    bool has_basic_constraints() const noexcept;
    bool is_ca() const noexcept;
    optional<int64_t> max_path_length() const noexcept;                      // nullopt: none
    bool has_key_usage() const noexcept;
    x509::key_usage key_usage() const noexcept;                              // the bits

    const vector<ext_key_usage>& ext_key_usages() const noexcept;
    const vector<string>& unknown_ext_key_usages() const noexcept;           // their OIDs
    const vector<string>& dns_names() const noexcept;                        // subjectAltName
    const vector<string>& email_addresses() const noexcept;
    const vector<ip_address>& ip_addresses() const noexcept;
    const vector<string>& uris() const noexcept;
    const vector<byte>& authority_key_id() const noexcept;
    const vector<byte>& subject_key_id() const noexcept;
    bool has_name_constraints() const noexcept;
    const vector<string>& permitted_dns_domains() const noexcept;            // and excluded_dns_domains
    const vector<ip_range>& permitted_ip_ranges() const noexcept;            // and excluded_ip_ranges
    const vector<string>& permitted_email_addresses() const noexcept;        // and excluded_email_addresses
    const vector<string>& permitted_uri_domains() const noexcept;            // and excluded_uri_domains
    const vector<string>& policies() const noexcept;                         // certificatePolicies' OIDs
    const vector<string>& unhandled_critical_extensions() const noexcept;    // their OIDs

    [[nodiscard]] expected<void, error> check_signature_from(const certificate& parent) const;   // Go's CheckSignatureFrom
    [[nodiscard]] expected<void, error> verify_hostname(const string& host) const;
    [[nodiscard]] expected<void, error> verify_ip(const slice<const byte>& ip) const;             // 4 or 16 bytes
    expected<void, error> verify_ip(const auto& text) const = delete;                  // a text (what converts to std::string_view) is not an address
    [[nodiscard]] expected<x509::chain, error> verify() const;                     // the system's roots, now, server_auth
    [[nodiscard]] expected<x509::chain, error> verify(const verify_options& options) const;

    friend bool operator==(const certificate&, const certificate&) noexcept;         // the same bytes
};

class certificate_pool {                             // a handle: copies share
public:
    certificate_pool();
    static expected<certificate_pool, error> system();
    static async::task<expected<certificate_pool, error>> async_system();
    static certificate_pool from_pem(const string& text);
    [[nodiscard]] static expected<certificate_pool, io::error> from_file(const string& path);
    [[nodiscard]] static async::task<expected<certificate_pool, io::error>> async_from_file(string path);
    void add(const certificate& c);                   // once: a certificate already in is not added again
    size_t append_pem(const string& text);           // how many were added
    size_t size() const noexcept;
    bool empty() const noexcept;
    const vector<certificate>& certificates() const noexcept;
    [[nodiscard]] bool contains(const certificate& c) const;
    certificate_pool clone() const;
};

struct verify_options {
    optional<certificate_pool> roots;                // nullopt: the system's
    certificate_pool intermediates;
    string dns_name;                                  // empty: no name checked
    slice<const byte> ip;                             // empty: no address checked
    optional<time::datetime> time;                    // nullopt: now
    vector<ext_key_usage> key_usages;                 // empty: server_auth
};

class name {
public:
    struct attribute { string oid; string value; bool text; };
    const vector<attribute>& attributes() const noexcept;
    bool empty() const noexcept;
    string common_name() const;                       // the last CN
    string serial_number() const;
    vector<string> country() const;                   // and organization, organizational_unit, locality,
                                                      // province, street_address, postal_code
    string to_string() const;                         // Go's pkix.Name.String()
};

class public_key {
public:
    key_kind kind() const noexcept;                   // none, rsa, p256, p384, ed25519
    bool has_value() const noexcept;
    const rsa::public_key& rsa() const;               // std::logic_error for another kind; so p256(), p384(), ed25519()
    const value_type& value() const noexcept;         // variant<monostate, rsa::public_key, p256::…, p384::…, ed25519::…>
    const string& algorithm() const noexcept;         // the SPKI's OID
};

struct ip_address { array<byte, 16> bytes; uint8_t size; };                  // 4 or 16 of them
struct ip_range { ip_address address; ip_address mask; bool contains(const ip_address&) const noexcept; };
struct extension { string oid; bool critical; vector<byte> value; };
```

`key_usage` has the nine bits of RFC 5280 §4.2.1.3 (`digital_signature` … `cert_sign`, `crl_sign`, `decipher_only`) as flags with `|` and `&`; `ext_key_usage` Go's fourteen (`any`, `server_auth`, `client_auth`, `code_signing`, `email_protection`, …, `microsoft_kernel_code_signing`); `signature_algorithm` Go's list without DSA (`sha256_with_rsa`, `sha256_with_rsa_pss`, `ecdsa_with_sha256`, `ed25519`, the MD5 and SHA-1 ones to be refused by name, `unknown`).

    for (const char* host : {"www.example.org", "a.b.api.example.com"}) {
        auto r = leaf.verify({.roots = roots, .dns_name = host, .time = at});
        if (!r && r.error().reason() == crypto::x509::reason::hostname_mismatch) {
            println("{}: not this certificate's name", host);
        }
    }
    auto later = leaf.verify({.roots = roots, .time = time::datetime::from_unix(2200000000, time::zone::utc())});
    switch (later.error().reason()) {
        case crypto::x509::reason::expired: println("in 2039: expired"); break;
        case crypto::x509::reason::unknown_authority: println("not from a root we trust"); break;
        default: println(later.error().message()); break;
    }
    auto unknown = leaf.verify({.roots = crypto::x509::certificate_pool(), .time = at});
    println(unknown.error().message());
}
```

Output:

```text
CN=www.example.com,O=Example\, Inc.
issued by Example Root CA, valid until 2036-01-01T00:00:00Z
  DNS www.example.com
  DNS *.api.example.com
  a P-256 key
verified: www.example.com <- Example Root CA
www.example.org: not this certificate's name
a.b.api.example.com: not this certificate's name
in 2039: expired
sgcl::crypto::x509: the certificate "CN=www.example.com,O=Example\, Inc." is signed by an unknown authority
```

The system's roots, and an IP address (`leaf_pem` as above):

```cpp
int main() {
    auto system = crypto::x509::certificate_pool::system();   // read once per process; a clone for each call
    if (!system) {
        eprintln(system.error().message());
        return 1;
    }
    println(system->size() > 100 ? "the system's roots" : "a few roots");

    // verify() with no roots takes the system's, at the time now
    crypto::x509::certificate leaf = crypto::x509::certificate::from_pem(leaf_pem);
    auto r = leaf.verify({.dns_name = "www.example.com"});
    println(r ? string("trusted by the system") : r.error().reason() == crypto::x509::reason::unknown_authority ? string("not from a root of the system") : r.error().message());

    // an IP address is bytes (net::ip_address gives them), never text
    const unsigned char ip[] = {192, 0, 2, 10};
    auto by_ip = leaf.verify_ip(ip);
    println(by_ip ? string("the certificate is for 192.0.2.10") : by_ip.error().message());
    auto as_name = leaf.verify_hostname("192.0.2.10");
    println(as_name ? string("matched as a name") : as_name.error().message());
}
```

Output:

```text
the system's roots
not from a root of the system
the certificate is for 192.0.2.10
sgcl::crypto::x509: "192.0.2.10" is an IP address, verified by its bytes (verify_ip, verify_options::ip), never against DNS names
```
