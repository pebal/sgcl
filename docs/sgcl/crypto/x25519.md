# sgcl::crypto::x25519

```cpp
#include "sgcl/crypto/x25519.h"   // or "sgcl/crypto.h"

namespace sgcl::crypto::x25519 {
    class public_key;
    class private_key;

    inline constexpr size_t public_key_size = 32;
    inline constexpr size_t private_key_size = 32;
    inline constexpr size_t shared_secret_size = 32;
}
```

`sgcl::crypto::x25519` is X25519 (RFC 7748), Go's `crypto/ecdh.X25519()`: Diffie–Hellman on Curve25519. Two
parties each make a [private_key](x25519-private_key.md) and send the other its [public_key](x25519-public_key.md);
each then computes the same 32-byte secret from its own private key and the other's public key, and nobody who saw
only the public keys can. It is the key exchange of TLS 1.3, SSH, WireGuard and Signal.

Written from RFC 7748, it is tested against the RFC's vectors (the single multiplications, the iterations 1 and 1000
— a million in a test run by hand — and §6.1's Alice and Bob), against OpenSSL on a thousand random key pairs and
peer keys of any 32 bytes, and against Go's `crypto/ecdh` on two thousand more.

**The implementation has not been through an independent cryptographic audit.**

## Rules

- **The shared secret is not a key.** Put it through a key derivation — [hkdf](hkdf.md) with a label of the protocol
  — and use what comes out for a cipher or a MAC, as TLS 1.3 and Noise do.
- **Any 32 bytes are a public key**, as RFC 7748 and Go have it: bit 255 is ignored and a value of p = 2²⁵⁵ − 19 or
  more is reduced. A public key of another length is refused (`errc::invalid_key`). A peer's key of small order makes
  the secret all zeros whatever the private key; [shared_secret](x25519-private_key/shared_secret.md) refuses it with
  `errc::invalid_key` (RFC 7748 §6.1), as OpenSSL and Go do.
- **Any 32 bytes are a private key**, too: they are "clamped" (the low three bits cleared, bit 255 cleared, bit 254
  set) each time they are used, not when stored, so `bytes()` gives back what was given, as Go's does; two private
  keys whose bytes differ only in the bits clamping sets therefore have the same public key and the same secrets.
  [generate](x25519-private_key/generate.md) takes them from [random](random.md).
- **Constant time.** The ladder of `shared_secret` takes the same 255 steps whatever the bits, swapping its points
  with masks rather than branches; the public key is computed by Ed25519's fixed-base multiplication, whose table is
  read whole with masks, and mapped to the Montgomery curve; the field arithmetic has no branch and no memory index
  that depends on a value. What is secret: the private key, the clamped scalar, every value of the ladder, the shared
  secret. What is not: the peer's public key and whether the result was zero.
- **A private key is a secret, so it is not copied.** It holds its 32 bytes in the object's own memory, is
  move-only, and is zeroed when moved from and when destroyed; the shared secret and `bytes()` are
  [secret\<32\>](secret.md), the exports [secret_bytes](secret_bytes.md), which zero themselves in turn. A key
  belongs on the stack or in a `unique_ptr`: in a managed object it stays in memory until the cycle that finds it
  dead.
- **Keys in files**: PKCS #8 (RFC 8410, OID 1.3.101.110) for the private key and SubjectPublicKeyInfo for the public
  key, byte for byte as OpenSSL writes them, and PEM, `PRIVATE KEY`, read and written straight into a `secret_bytes`.
  Reading is strict DER; another algorithm's key is `errc::unsupported`, broken DER `errc::malformed` with the
  offset. [encoding::pem](../encoding/pem.md) is for public PEM (certificates); its bytes are managed, where a private
  key's must not be.

## Example

```cpp
#include "sgcl/crypto.h"
#include "sgcl/encoding.h"
#include "sgcl/io.h"

using namespace sgcl;

int main() {
    // RFC 7748 §6.1's keys; a program makes its own with generate()
    auto alice = crypto::x25519::private_key::from_bytes(
        encoding::hex::decode("77076d0a7318a57d3c16c17251b26645df4c2f87ebc0992ab177fba51db92c2a"));
    auto bob = crypto::x25519::private_key::from_bytes(
        encoding::hex::decode("5dab087e624a8a4b79e17f8b83800ee66f3bb1292618b6fd1c2f8b27ff88e0eb"));

    // each side sends the other its public key, 32 bytes
    auto bob_public = bob->public_key();
    println("Bob's public key: {}", encoding::hex::encode(bob_public.bytes()));

    // and each computes the same secret
    auto shared = alice->shared_secret(bob_public);
    auto same = bob->shared_secret(alice->public_key());
    println("{}", shared == same ? "the same secret" : "different secrets");

    // a key for a cipher is derived from it, never the secret itself
    crypto::secret_bytes key = crypto::hkdf_sha256::derive("salt", shared, "chat v1 key", 32);
    crypto::chacha20_poly1305 aead(key);

    // a peer's key of small order gives nothing
    auto zero = crypto::x25519::public_key::from_bytes(array<byte, 32>{});
    auto refused = alice->shared_secret(zero);
    println("{}", refused.error().message());
}
```

Output:

```text
Bob's public key: de9edb7d7b7dc1b4d35b61c2ece435373f8343c85b78674dadfc7e146f882b4f
the same secret
the shared secret is zero: the peer's key is of small order
```
